Global view

Architecture overview

BG Eraser is a static single-page app. There is no backend. Every image is processed on the user's device, and the only network call at run time is the one-time model download.

One tier

A React app served as static files. No API, no database, no environment variables.

Local inference

The RMBG-1.4 model runs in the browser through Transformers.js and ONNX Runtime Web.

Canvas pipeline

Pixels are handled with the Canvas 2D API. Output is a transparent PNG at the original size.

System diagram

What runs where, and what crosses the network.

Design principles

Privacy by design

No backend means no place to send images to. The app has no analytics.

Full resolution output

The model sees at most 1024 px. The mask is then resized and applied to the original pixels.

Simple state

One page component owns the state. Utilities are plain functions with no React dependency.

Static deploy

make build produces dist/. Any static host works.

Image status flow

How the queue works

  1. EnqueuehandleFilesSelect creates items with status pending and pushes their ids to processingQueueRef.
  2. GuardprocessNextInQueue returns early if the queue is empty or isProcessingRef is set. Only one image runs at a time.
  3. ProcessIt loads the file with loadImage, calls removeBackground, and stores the result blob and an object URL.
  4. FinishIn a finally block it shifts the queue, clears the flag, and schedules the next item with setTimeout.

Undo: saveToHistory() is called before crop, upscale and manual edits. Ctrl/Cmd+Z pops the last snapshot.

AI pipeline

Implemented in src/utils/backgroundRemoval.ts. The function removeBackground(img, onProgress) returns a PNG Blob.

Step details

  1. DownscalecreateModelCanvas keeps the aspect ratio and limits the longest side to MAX_MODEL_DIMENSION = 1024.
  2. Load model and processorAutoModel.from_pretrained('briaai/RMBG-1.4', { device: 'webgpu' }) and an AutoProcessor with a fixed config (mean 0.5, std 1, size 1024x1024). The browser cache keeps the files after the first download.
  3. InferThe processor produces pixel_values. The model returns output, a mask tensor.
  4. Resize the maskThe mask is converted to uint8 and resized to the original width and height with RawImage.resize.
  5. FeatherapplyAlphaMatting blurs the mask with a Gaussian kernel (radius 3) and writes it into the alpha channel of the original pixels.
  6. Encodecanvas.toBlob('image/png') returns the transparent PNG.

Progress is reported at fixed steps: 5, 15, 40, 50, 75, 85, 95, 100.

Manual mode

Implemented in manualBackgroundRemoval.ts and ManualEditor.tsx. No model is used.

  • The user picks colors from the image (getColorAtPixel) or from a color input (hexToRgb).
  • Each pixel whose RGB distance to a picked color is below the tolerance (default 30) gets alpha 0 (removeColorFromImage, colorDistance).
  • The result is returned to Index through onProcessed(blob, url), after an undo snapshot.

Crop, upscale and export

Crop

CropEditor is a canvas UI with free or fixed aspect ratios and zoom. It returns a new blob through onCropApplied.

2x upscale

upscaleImage draws the image at 2x with canvas interpolation, then applies a 3x3 sharpen kernel. It is not an AI upscaler. Both the result and the original are upscaled.

HEIC input

heicConverter loads heic-convert/browser on demand and returns a JPEG File at quality 0.9.

Export

PNG download, clipboard copy (navigator.clipboard.write), or a ZIP of all results built with JSZip.

Images can also come from drag-and-drop on the whole page, a file picker, or a paste event.

Build, test and CI

Stack

React 18, TypeScript, Vite (SWC), Tailwind CSS v4, shadcn/ui, Transformers.js, JSZip, heic-convert.

Tests

Vitest with Testing Library. A canvas helper in src/test/canvas.ts mocks canvas APIs.

CI

GitHub Actions, Node 22, four parallel jobs: lint, typecheck, test with coverage, build.

make install   # npm ci
make dev       # http://localhost:8080
make check     # lint, typecheck, test, build
make build     # static site in dist/

Limits and known gaps

Honest list. These come from reading the code, not from a security audit or benchmark.

  • WASM fallback is untested. The code requests webgpu. The comment says it falls back to WASM, and the README says this is not tested.
  • Model input is capped at 1024 px. Fine details such as hair are limited by that size.
  • Feathering is a plain Gaussian blur of the mask. It is not a true alpha matting algorithm, although the function is named that way. It also loops over a kernel per pixel on the main thread, so very large images can freeze the UI for a moment.
  • Memory. Large images use a lot of browser memory. Object URLs are revoked on reset, but not on every intermediate edit.
  • cropToContent is unused. imageCrop.ts is only referenced by its own test. It can be wired in or removed.
  • Large page component. Index.tsx mixes queue, export and editing logic. Splitting it into hooks would help testing.
  • Model license. RMBG-1.4 has its own license terms. Check them before commercial use.
